# ADR 0001: Utilização de modelo de saída de dados HL7 para a API de microserviços

**Status:** Aceito.

**Contexto:** Softwares públicos de saúde precisam disponibilizar os dados de seus pacientes a micro serviços como centros de pesquisas, aplicativos, universidades e órgãos de dados públicos como RNDS ou DataSUS. Entretanto, o uso de uma saída JSON customizável exigiria de parceiros e de órgãos públicos à adaptabilidade a nossa saída de dados, assim, dificultando colaborações futuras entre serviços, aumentando a defasagem do código e dificultando a criação de serviços em torno do nosso software.  

**Decisão:** Se faz necessário o uso de uma saída padrão internacional para troca de dados de saúde chamado HL7. Assim, permitindo uma troca de dados entre serviços e excluindo a necessidade de outros serviços a se adaptarem aos nossos payloads.  

**Alternativas consideradas:**  
* **Modelagem de payloads proprietários:** descartado porque aumentaria drasticamente o custo de mapeamento de dados a cada nova integração governamental ou laboratorial.  

**Consequências:**  
* **Positivas:** conformidade nativa com as exigências governamentais brasileiras; padronização rigorosa entre todas as saídas de dados da nossa API; facilidade em conexão com outros serviços seja de caráter público, privado ou de pesquisa.  
* **Negativas:** curva de aprendizado inicial elevada para os 40 desenvolvedores dominarem o modelo de recursos e extensões do FHIR.
