# ADR 0007: Separação entre Event Sourcing e Log de Auditoria

**Status:** Aceito.

**Contexto:** O sistema precisa manter o histórico das alterações realizadas no prontuário eletrônico e também registrar acessos e visualizações de dados sensíveis. O uso de Event Sourcing permite registrar eventos que modificam o estado do domínio, porém não garante o registro de operações de leitura, como a visualização de um prontuário. Utilizar o Event Store para registrar todas as consultas e acessos também aumentaria desnecessariamente seu volume e complexidade.

**Decisão:** Separar o Event Sourcing do mecanismo de auditoria de acessos. O Event Sourcing será utilizado para registrar eventos que alteram o estado do domínio e o histórico clínico quando a reconstrução temporal trouxer valor ao sistema. Os acessos, visualizações, consultas e outras operações sobre dados sensíveis serão registrados por uma camada dedicada de auditoria, utilizando um AuditLogger integrado aos interceptors ou middleware da API e armazenando os registros em uma estrutura Append-Only separada.

**Alternativas consideradas:**  
* **Utilizar somente Event Sourcing:** descartada porque eventos de leitura não alteram o estado do domínio e, portanto, não são naturalmente representados pelo Event Sourcing.  
* **Registrar acessos como eventos de domínio:** descartada porque mistura responsabilidades distintas e pode aumentar excessivamente o volume do Event Store, prejudicando sua utilização para reconstrução do estado.  
* **Não registrar operações de leitura:** descartada porque o sistema precisa manter rastreabilidade dos acessos a dados sensíveis para fins de auditoria e conformidade.

**Consequências:**  
* **Positivas:** separação clara entre histórico do domínio e auditoria; registro explícito de acessos e visualizações; redução da sobrecarga no Event Store; melhor organização dos mecanismos de auditoria e conformidade; possibilidade de aplicar políticas específicas ao armazenamento dos logs de auditoria.  
* **Negativas:** aumento da quantidade de componentes e estruturas de armazenamento; necessidade de manter e monitorar o AuditLogger; maior complexidade para correlacionar eventos de domínio e registros de auditoria quando necessário.
